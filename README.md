# Mukhtabir Android

Native Kotlin/Compose client for Mukhtabir Django. Arabic/English, RTL, themes and density settings; Android 6+ (API 23), SDK 34, Java 17. Contributor rules: [Agents.md](Agents.md).

## Features

- Offline first-launch demo: bundled science questions, quick study, timed exam, recall and result review; no account/server/download required. Demo progress is separate from private learning.
- Ordinary study/exam/recall, book/category/tag selection, shared practice launcher, targeted practice from results, confidence/reflection, session flags/maps and final review. Bilingual comparison respects answer/explanation reveal rules.
- Revealed correct/wrong choices use a shared 1dp feedback border with more saturated theme-derived green/red and inline answer-status labels with decorative check/cross icons that wrap when needed; completed review distinguishes unanswered questions and labels selected answers even when the key is unavailable; unrevealed choices retain subdued selection styling without feedback animations. During active questions, save indicators overlay content rather than shifting it; scroll resets remain tied to navigation.
- Question images share bounded byte/pixel checks, sampled decoding and a memory-only zoom/pan viewer with keyboard/TalkBack sliders, explicit reset and close controls for online and offline readers.
- Default spacing uses tighter gaps/card padding; Compact reduces them further while preserving 48dp touch targets and text scaling.
- Amiri is the default font in Arabic and English; explicit font selections are retained. Reading comfort: saved text size, line/paragraph spacing, reading width and app font, including Help/Privacy readers; offline study preview and independent reading reset.
- Welcome, startup, login and saved-login recovery share a scrollable, keyboard-aware entry layout capped at 520dp. The first welcome follows the animated wordmark splash and centers sample practice first, server connection second and a single-language selector last. Demo and downloaded practice have separate cards with filled secondary-color buttons; login retains account access first. Login keeps its password visibility toggle/reset, with Help/Privacy/server changes under expandable options. Offline practice uses one back/title bar with two-line wrapping titles and fixed navigation controls; list-only guidance stays out of questions. Save feedback remains compact and repeated status text is suppressed.
- Continue learning, daily planner progress, downloaded collections, bookmarks, personal History, mistakes, fragile knowledge, analytics, groups and knowledge/case browsing. Home and Activity share calendar alignment and intensity levels, including session-only activity.
- Filter labels explain any-tag matching and combined restrictions. Import file cards start collapsed with status, reports/error details and explicit uncertain-outcome review; destructive actions name what they remove.
- Shared labelled toggle rows, wrapping actions/adaptive search, pagination and destructive confirmation roles; draft editors reuse field groups and keyed choice rows. Master exams reuse the adaptive session header, stable clock, navigation and question-map chips; short-height/large-text layouts scroll the chrome while retaining grace and recovery rules.
- Permissions protects unsaved role/user edits before target changes or exits. Categories scrolls editor/recovery controls together, guards busy exits and flushes the latest encrypted draft before leaving. Exam draft forms mark field errors, reveal affected sections and focus/scroll to the first invalid field on each submission.
- Side navigation keeps Settings above the scrolling destinations and adds a Settings shortcut to the main top bar. Learn, Review, Master exams, Account and Help come before content creation, moderation and administration; everyday sections start open, and the current section opens automatically. Short-height/large-text drawers scroll the full header and menu.
- Capability-gated authoring, private drafts, master exams, moderation and administration. Django is authoritative; personal History always uses the signed-in user, and all-user history requires its separate capability.

## Setup

Use JDK 17 and SDK 34; set `ANDROID_HOME` or ignored `local.properties` (`sdk.dir`). The optional [build helper](build.py) opens an interactive input menu when run without arguments: choose the output type, cached-only dependencies and build/install or preview. It also accepts direct command-line options, checks the toolchain and reports output paths. It works from any working directory; use `python` instead of `python3` where appropriate.

```bash
python3 build.py                                # Interactive menu
python3 build.py --interactive --dry-run         # Menu with command preview only
python3 build.py --help
python3 build.py release --format aab --dry-run  # Show command; no Java/Gradle execution
python3 build.py --check                        # Check JDK/SDK; no Gradle execution
# Build/install commands, when explicitly authorized:
python3 build.py debug                          # Debug APK without prompts
python3 build.py release                        # Release APK (unsigned)
python3 build.py release --format aab            # Release AAB (unsigned)
python3 build.py debug --format aab              # Debug AAB
python3 build.py --install                      # Debug APK; install on connected compatible devices
python3 build.py --offline                      # Debug APK using cached dependencies
```

Release signing stays external; the helper does not create keys, sign release outputs or run automated suites. `--offline` also requires the wrapper distribution to be cached to avoid its initial download. Direct `./gradlew assembleDebug` and `./gradlew installDebug` remain available. Gradle user/dependency/daemon caches stay in the building account’s `~/.gradle`; project/task caches and module outputs use `~/.gradle/mukhtabir/<checkout-hash>/`. APK/AAB originals are in `build/app/outputs/{apk,bundle}/<variant>/` beneath that account root. Successful packaged artifacts are copied to that account’s `Desktop/Mukhtabir/<variant>/` (including Linux XDG Desktop settings; AABs use `Mukhtabir/bundles/<variant>/`), named `Mukhtabir-<version>-app-<variant>.apk`. Override Desktop with `-Pmukhtabir.desktopDir=/absolute/path` or `MUKHTABIR_DESKTOP_DIR`; older copies are retained. Existing shared `.gradle/` and `app/build/` folders are left untouched and no longer used by the wrappers. This project has no native libraries or ABI splits, so separate CPU builds are unnecessary.

Versioning follows the ShiftReport launcher pattern: `gradle/app-version.properties` is the shared last-reserved version across both OS accounts. Full packaging task names through `./gradlew`, `gradlew.bat` or `build.py` reserve one patch/code pair per invocation, formatted `major.minor.patch.yyyymmdd` (Asia/Damascus date). The first reservation after `0.1.3` / code 4 is `0.1.4.<date>` / code 5. Failed/interrupted attempts retain their reservation; help, clean, IDE sync and dry runs do not increment. The POSIX helper locks the stable `gradle/` directory and atomically replaces the counter, avoiding another account’s file ownership; both accounts need write access to that source directory. Keep the version file when copying the project; do not reset it after builds. Python 3.9+ and the Asia/Damascus timezone database are required for automatic reservation. Explicit version overrides must provide both `-Pmukhtabir.versionCode=N` and `-Pmukhtabir.versionName=A.B.C.yyyymmdd`; `-Pmukhtabir.autoVersion=false` deliberately reuses the last reservation. Android Studio/direct system Gradle use the stored version; use the wrappers/helper for automatic increments. Account settings/output paths also apply during IDE sync; the IDE's Gradle User Home should remain account-local.

First launch groups sample practice first, server connection second and the saved-language picker afterward; server setup uses the same bounded form width. Learning/setup confirmation buttons name their action. Login options, connection-file slots, connection help and advanced practice controls share the same disclosure component; Back returns to the welcome screen before a server is configured. Enter a reachable HTTP/HTTPS origin or full deployment-prefix `/api/v1/` URL. Manual input starts blank; saved manual addresses reopen. Emulator host access uses `10.0.2.2`; a phone needs a reachable LAN address or USB `adb reverse tcp:PORT tcp:PORT` with its actual backend port. Phone `localhost` means the phone.

A build-time URL can come from `MUKHTABIR_API_BASE_URL`, ignored `server.properties` (`api.base.url`), then `local.properties`; this does not replace the phone-selected address. See [server.properties.example](server.properties.example).

HTTP requires confirmation and is restricted to the selected origin; HTTPS cannot downgrade. Private HTTPS needs a trusted Android-installed CA and a certificate matching the host/IP. Never disable chain/hostname validation. Align Django hosts, CSRF origins, cookies and proxy scheme with the actual endpoint: [backend startup](../backend/docs/guides/START_HERE.md).

### Connection files

Admin Settings can export v1 JSON; the endpoint is `bundle.connection.endpoint.api`. Files are unencrypted convenience data, not credentials or trusted server identities. Import accepts at most 64 KiB and retains three numbered slots without original filenames/URIs. Imported addresses stay hidden in controls; manual entry never copies them. Saving/replacing a slot does not activate it; switching requires confirmation.

Address changes clear sign-in/reminders, restart navigation and require reauthentication. Encrypted files remain in their local server profile. Only explicit **Same server, different address** associates an unfamiliar alternate address with that profile; imported identities never merge profiles.

## Offline and recovery

- **Downloaded ordinary sessions:** encrypted owned snapshots/images and ordered local answers. Study feedback follows a saved answer; exam feedback remains hidden. Explicit Sync reconciles current index/slot and acknowledgement before removing queued data. Pause/server Finish require confirmation; uncertain writes are never automatically replayed.
- **Deadlines:** exam time continues offline; answers must reach the server before its deadline. Only downloaded study can finish on device for later explicit synchronization. Local completion does not establish server History/learning credit.
- **Offline collections:** selected downloads/sync require `tests.start`; full-bank/focused catalogue download additionally requires `tests.download_full_bank`. Without that grant, the server enforces a cumulative selected-question budget (currently 200 distinct IDs); deleting local copies does not reset it. Admin Permissions controls the grant. Interrupted downloads retain checkpoints; text-only copies and explicit update/review are supported.
- **Storage:** immutable encrypted pack files and an encrypted account/server index; no authenticated HTTP disk cache. Freeze completion UUIDs, bodies, answers and occurrence times across retries. Rename/flag/display metadata must not alter signed packs or upload identities. Failed reads/commits retain recovery and block unsafe changes.
- **Offline launch:** retained downloads and the bundled demo can open during startup connection checks and after a saved-login read fails. Recovery keeps Retry visible and groups sign-out/server changes under More options. Login also offers downloads when eligible and the demo.
- **Access:** ordinary login expiry permits retained local-only downloaded practice; uploads require fresh authentication. Explicit logout, another account or confirmed account expiry revoke/clear private storage. Changing server address retains isolated files but requires reauthentication. Revoking download permission cannot remotely erase an offline device.
- **Drafts:** retain readable content, selections and confirmed results on failure. Compare current server state before explicit retry/discard. Task saved state holds account-checked navigation metadata, not private answer/question bodies; sensitive drafts use memory or existing encrypted recovery. Never log secrets/private responses.

Server contracts: [learning](../backend/docs/contracts/learningConsistency.md), [writes/recovery](../backend/docs/contracts/writeRecovery.md), [schema readiness](../backend/docs/contracts/schemaReadiness.md). Matching deployment/schema must be verified; this README does not authorize setup or migrations.

## Development

`app/src/main/java/com/mukhtabir/android/`: `core` owns storage/preferences/navigation/container, `data` owns auth/HTTP/DTOs/services, `ui` owns Compose screens/shared controls (`ui/navigation/AppDrawerContent.kt` owns the drawer; `ui/more/MoreScreen.kt` only restores the legacy More destination), and `util` owns formatting. Keep endpoints aligned with current Django and applicable Vue behavior. Runtime `/config/` supplies limits, pagination and role options with safe fallbacks; optional reads must not block startup.

Question editing separates its serializable state (`QuestionEditorState.kt`), ViewModel (`QuestionEditorViewModel.kt`), route/form (`QuestionEditorScreen.kt`) and previews (`QuestionEditorPreview.kt`). Quiz UI separates setup, active questions, results and shared controls; `QuizUiState.kt` holds state models. `QuizSetupController.kt` owns setup selection/filter/count jobs, and `QuizSetupStateStore.kt` owns account-checked lightweight saved-state mapping. `QuizViewModel.kt` retains session writes, timers, download/sync and uncertain-outcome recovery.

Library listing and question detail have separate state/ViewModel/UI files; library filters/cards stay in dedicated components. Dashboard, planner, analytics, history and admin users separate state/coordinators from screens. Personal and admin settings are separate; analytics charts and master-exam management/editor/fields/presentation have dedicated files. API models/services are grouped by domain in `data/remote`, retaining class packages and serialization contracts.

`MukhtabirApp.kt` owns authentication/startup; `ui/navigation/AuthenticatedAppShell.kt` owns shell chrome, with route IDs, shared shell state, navigation helpers and destination registrations in adjacent files. Route capability checks remain beside registrations; callbacks share the shell’s live Compose state.

Reuse shared controls/tokens, session chrome, practice launcher, result filters, question maps/cards and locale resolver. Keep 48dp targets, selected/non-color states, keyboard focus, RTL, large text, reduced motion and existing fonts/themes. Announce errors/outcomes, never ticking clocks. Theme/palette changes must coordinate web/PDF exports. Frozen results and reveal restrictions remain authoritative; Bookmarks filters explicitly apply to the loaded page. Missing translations/source dates must be labelled rather than invented.

Launcher master: [artwork/app_icon.png](artwork/app_icon.png); monochrome icon: [ic_launcher_monochrome.xml](app/src/main/res/drawable/ic_launcher_monochrome.xml). Regenerate with `python3 artwork/generate_launcher_icons.py` (FFmpeg) or `python3 artwork/generate_startup_wordmark.py` (Fontconfig/Pango/Cairo). Labels remain **مُختبِر**; asset conversion does not verify an installed launcher/cache.

Useful diagnostics: `adb devices -l`, `adb shell pidof com.mukhtabir.android`, `adb logcat --pid=PID -v threadtime`. Release signing stays outside version control; verify minified serialization/navigation before distribution.
