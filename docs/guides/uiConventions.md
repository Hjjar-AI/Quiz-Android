# Native UI conventions

Updated 2026-10-10. Maintained rules for Android presentation; [shell review/fixes](../reference/androidUiReview.md) and [device matrix](../verification/manualVerification.md). Match functional Vue/Django contracts while using native controls.

## Page structure

- Use `AppPageHeading` for routed page titles. It exposes heading semantics and stacks commands at narrow widths/enlarged fonts. Place related page commands in its `action` slot; wide layouts reserve readable space for the title. The dashboard uses `keepActionInline` for its single refresh icon beside the welcome title at the logical end; keep its subtitle below. Brand typography and result/metric values can use their deliberate larger styles.
- Use `AppLayoutTokens.pagePadding` for ordinary page gutters, `LocalAppSpacing` for density-sensitive page/section gaps, and `AppLayoutTokens.controlGap` for independent controls. Startup/login, dialog, image and specialized session layouts can retain deliberate padding.
- Use `AppSection` for collapsible sections; collapsing retains composition/drafts and removes hidden content from focus traversal. Field validation uses `revealError` plus a transient `revealRequest` counter to reopen the affected section on each deliberate invalid submit.
- Use `AppCard` for neutral content containers. Whole-card activation and nested actions must remain independent; preserve existing selected/checked semantics and ownership checks.
- Answer-choice Markdown uses noninteractive text so the whole choice activates its parent control; ordinary reading content retains text selection. Confidence starts at Certain (3), with saved values preserved. Confidence/error-reason sections start collapsed and show the current value; the default wrong-answer reason is Unknown. Opening/closing sections performs no writes. The native shell keeps 48dp controls with reduced vertical padding and a 36dp visible bottom-tab frame within a 48dp selectable target that can grow with text. Library gutters/cards use the shared compact spacing tokens.
- Full question readers/previews use `QuestionTextCard`, `QuestionChoiceCard` and `ExplanationCard`. Explanations use the subtle choice shade, selectable Markdown and shared card insets; blank text produces no empty card and reveal/answer guards stay with callers. `AppTheme.questionSurfaces` derives opaque related shades from each palette's background and foreground: question 11%, choices 5.5%, with a subtle outline. Selected choices use a subtle opaque primary tint, thicker outline and native selection semantics; results retain correct/wrong labels and soft feedback blends. Preserve whole-choice selection, noninteractive answer Markdown, selectable question text and 48dp targets.

## Commands and feedback

- Use `AppButton` for a primary command, `AppOutlinedButton` for secondary commands, `AppTextButton` for lightweight/dialog commands and `AppIconButton` for labelled icon commands. All share a minimum 48dp target; keep meaningful icon descriptions.
- Explicit delete/discard/database replacement controls use `AppDangerTextButton` or `AppDangerOutlinedButton`. Labels and existing confirmation/recovery rules remain essential; color only supplements them. Mixed-action dialogs must classify the actual action before choosing a destructive style.
- Use `AppActionRow` to wrap independent commands/chips with horizontal and vertical gaps. Set `fillWidth=false` for a heading's command slot. Keep Row for aligned metadata, checkbox/switch rows or intentionally weighted session navigation; keep horizontal scrolling for deliberate question/filter strips.
- Use `AppLoadingIndicator` for ordinary reads/commands: three theme-colored dots with a continuous 1.4-second pulse, mirrored in RTL. Auth buttons use `compact=true` and their inherited content color. Disabled system animations show static dots; expose the localized loading label and indeterminate progress semantics without per-frame announcements. Keep determinate bars for actual completion/progress.
- Use `ErrorState` for safe API/read failures, field error/supporting text for validation, and `AppSuccessText` for saved confirmation. Errors and outcomes expose polite announcement semantics. Never announce ticking timers or continuously changing progress.
- Use `AppPagination` for ordinary one-based pagers. The caller owns page state, authority, failed-page retry and busy guards; pass the existing previous/next enabled conditions. Localized page status uses number-format helpers. Specialized reports must retain their own totals/context.

## Behavior and verification

Launch branding: the native starting window shows a centered vector outline of **مُختبِر**, with light/night colors. Android 12+ uses a 900ms RTL reveal with a moving writing dot inside the system splash mask; older versions show the complete word immediately. Native artwork is outlined from the bundled Amiri font and fitted to the circular mask using its actual outline/control-point bounds, including vowels. The Compose session-restoration screen shows a 104sp Amiri title (scaled to fit narrow/large-text screens) with a continuous 900ms reveal, a softly glowing writing dot that fades on completion, and the shared dots/offline action. Full shaped text stays intact, reduced motion displays the complete word, and automatic readiness handoff waits for the actual name-reveal completion; zero motion completes immediately. Regenerate the native vector with `/usr/bin/python3 artwork/generate_startup_wordmark.py` (host Fontconfig/Pango/Cairo libraries); this does not build/package the app.

Presentation components never send network requests, retry uncertain writes, reset selection, clear drafts or grant capabilities. Busy/ownership/capability/unknown-write/session guards stay in routes and handlers. The shell consumes keyboard and Scaffold insets; do not add duplicate form padding without checking inset consumption. Preserve native file providers and hidden imported server addresses.

Changes must include matching English/Arabic resources. Verify RTL, 320/360dp widths, 200% text, keyboard, themes/contrast, focus and TalkBack on devices before claiming rendered correctness. Lexical/resource checks do not establish compilation or accessibility. Builds/suites/migration work still require the explicit authorization defined in the agent rules.


## Launcher artwork

Normal and round icons use the same mipmap resource. Keep density PNG fallbacks and API 26+/33+ adaptive/themed resources together; do not point the manifest to a drawable-only launcher asset. Full-color variants use the transparent `artwork/app_icon.png` mark; themed launchers use a separate outline vector. Regenerate fallbacks with `python3 artwork/generate_launcher_icons.py` (FFmpeg required); see [launcher artwork](launcherArtwork.md). The application/installer and launcher labels are **مُختبِر** in every language; in-app names use their existing localized resource. User-installed launchers may cache icons, so assess the rebuilt installed app and refreshed launcher before diagnosing a fallback.

## Density and question reading after the posted audit

Use `AppTheme.spacing` / `AppLayoutTokens` for section/content/tight gaps and standard/dense/library card padding. Auth keeps a named 16dp gutter; question/library reading retains its 12dp outer gutter; picker/image/menu/heading limits have distinct semantic tokens. `AppCardBody`, `AppToggleRow` and `AppListRow` standardize presentation while callers retain callbacks, semantic roles and guards. Do not blanket-replace media geometry or shrink the 48dp hit-target minimum.

Native Markdown/policy text uses shared `NativeTextStyle` with the Compose requested size/line height and content direction. Medical spans can still need natural font height. Full question readers offer a local language selector; locale lookup is shared and translated stem/options apply together. Missing translated explanations and separately untranslated cases are explicit. Source/reference/category/tag identities and frozen result text are not automatically translated. Root navigation is shared; detail reads reuse concrete targets; write/session/draft guards remain independent.

## Compact vertical rhythm and drawer controls

All ordinary card bodies use `cardInsets`/`denseCardInsets`, including management/authoring, analytics, learning, account and result screens; do not apply the horizontal `cardPadding`/`denseCardPadding` scalar equally to all four sides. Auth uses `authInsets` (16dp horizontally/6dp vertically) and shared control gaps. Profile/tip cards, page-heading/section rows and loading labels use shared insets/gaps too. Minimum control size remains 48dp.

Standard page insets use 8dp horizontal gutters and 6dp vertical padding. `AppLayoutTokens.pageInsets` owns whole-page padding; `pagePadding` remains the horizontal-gutter scalar. Normal/compact density section gaps are 6/4dp and control gaps 4/3dp. Normal/compact card insets are 8/6dp horizontally and 4/3dp vertically; dense cards/rows use 6/4dp horizontally and 3/2dp vertically, and library cards use 6/4dp. Primary button content uses 12dp horizontal/2dp vertical padding; secondary actions use 10dp horizontal and density-aware 1–2dp vertical padding. Outlined secondary frames are 36dp within 48dp clickable surfaces. All retain 48dp minimum touch targets; feedback blocks use 10dp vertical padding. Shared Compose typography disables extra platform font padding while preserving existing line heights and Arabic diacritic room; native Markdown already omits font padding. Offline material cards use dense horizontal/vertical insets rather than the horizontal scalar on all four sides.

The drawer has a 20dp palette icon at the logical end of its title row, inside the shared 48dp icon-button target. It opens the existing named-theme menu; Dark is a selectable theme and has no separate mode switch. About and Privacy are small standalone drawer destinations outside Account, with selection/disabled guards. Settings sections start collapsed; the page-size preference is labelled “Maximum questions per page” / «الحد الأقصى للأسئلة في الصفحة».

Arabic is the language fallback for unsaved preferences and first server setup. Saved Arabic/English/System selections remain respected, including explicit device-language following. Device checks for RTL/header placement, screen-reader selection, narrow/large-text layouts and the revised vertical rhythm remain required.

## Session setup

Session secondary actions live behind one labelled tools menu: pause, pending Sync, download/deadline guidance, sound and optional haptics. Keep the timer/progress/primary navigation visible and quick Sync available when answers are pending. Haptics default off, use shared `performAppHaptic` with device settings respected and a permitted short vibrator fallback if native feedback is rejected, and distinguish accepted selection from server-confirmed saves; never replay feedback on returning from the background or treat a local/failed sync as server confirmation. Result filters operate on frozen result rows, retain original numbering and summary totals, and separate incorrect answered rows from unanswered rows.

Explanation section links derive from actual rendered Markdown headings and scroll within the existing reader; plain text must not gain invented sections. Shared images reserve the same bounded themed area during loading/error/Retry/success only when a URL exists, and fit without cropping. Absent images/case/translation metadata reserve no dummy panels; independently fetched bookmark state loads within its existing fixed control target. Native heading jumps, image geometry and haptic/menu accessibility remain device verification requirements.

Ordinary active sessions use a compact fixed question/timer header, thin answered-progress bar and one bottom row: Previous icon, question navigator icon and primary Next/Finish. The dialog navigator reuses the existing answered/current question strip. Keep 48dp targets and rely on the shell's consumed system insets rather than adding duplicate navigation-bar padding. Downloaded-session status stays short beside Sync; details retain synchronization/deadline guidance and failures retain visible recovery controls. Study choice labels live inside the highlighted cards, with color plus explicit correct/selected-wrong text. Question typography is stronger than choice body text; explanation headings/body text use shared styles and their short opacity reveal skips motion when system animations are disabled. Keep the question text card full width. Bookmarking is an independently guarded session-tools menu item; reads/writes must not block local answering or replay uncertain writes. Show answer correctness inside the choice cards only, without a duplicate status heading before the explanation.

Active book/category/tag filters are removable wrapping chips outside the optional panels; removal keeps the other selections and can recover from invalid or unavailable scoped metadata. Resume cards show mode, question position, answered progress and known/unknown pending local state before the primary Continue action. Completed-result summaries lead with score/accuracy/unanswered counts; per-question reviews and breakdowns can opt out of composing collapsed read-only content. These presentations retain server reveal/deadline, encrypted local storage and confirmation/recovery rules.

Keep setup sections stacked: mode, question pool (All questions by default), optional book restriction for the bank, shared optional category/tag filters, other options, and count/Start. Optional panels start collapsed and show active selections/options in their headers. Use compact wrapping chips without checkmarks, with selected theme colors/weight and native selection semantics. Same-selection taps preserve state; book changes prune only incompatible chips after a successful scoped read. Show blocking reasons near Start, preserve entered counts, and allow whole-book sessions without waiting for optional facet metadata when no scoped chips are selected. Compilation/device/RTL/large-text verification remains separate from source checks.

Dashboard sections use controlled AppSection expansion and omit read-only content composition while closed. Keep data and request state in the account-scoped ViewModel, fetch on explicit expansion, cache successful snapshots, and refresh only open sections; closed cached sections become stale for their next open. Local navigation/recovery sections need no server reads. Use full-width stacked dashboard sections; Today comes first and initializes expanded when study is permitted, while all other sections initialize collapsed. Internal mode/metric tiles retain their responsive grids.

## Selected presentation polish (2026-10-13)

Use the named theme medium shape for related shared cards, choices, explanations, buttons and setup chips. Questions have the stronger outline; secondary cards use quieter borders. Opaque gentle feedback blends retain on-surface text, correct/wrong borders and labels. Ordinary choices use a font-scaled number gutter with first-line alignment, a thicker selected outline and radio semantics; avoid redundant checkmarks and empty icon columns. Shared card gutters apply consistently, while active session spacing uses the content gap.

Secondary outlined actions have a 36dp visible frame within a minimum 48dp clickable/keyboard-accessible Material surface; the surrounding inset remains actionable. Shared secondary padding is density-aware, icon/loading slots are 20dp and disabled text remains readable while handlers stay disabled. Labels use medium weight and Arabic line height bounded by natural font metrics; body reading retains its ratio. Counts/hints use on-surface-variant colors. Compact explanation block/heading styling applies only to explanations, preserving actual Markdown and section navigation. Reserve clock geometry for localized hours/minutes/seconds and keep sizing text out of accessibility; stack clock captions at narrow widths/enlarged fonts. Device verification is required for font/diacritic safety, focus/touch bounds, contrast and timer wrapping.

## 2026-10-13 session clarity and richer themes

Active exams use a neutral selected-choice outline/tint, preserving radio semantics; feedback labels/explanations stay gated to study/recall. Next/Finish uses the shared compact 36dp visible primary frame within a 48dp clickable surface and grows with text; Retry/Sync remain secondary. The scrolling content and bottom row are separate measured siblings under the existing consumed shell/IME insets. Failed images use a 96dp scrollable panel containing their own Retry; loading/success retain the fitted image area, so error transitions intentionally change height. Session status distinguishes local pending data, syncing, sync failure, confirmed synced answers and storage recovery without claiming local-only answers reached the server.

Named light backgrounds/cards now have visible palette tones, with stronger distinctions among lavender, rose, aqua, blue-grey, sage-grey, gold, parchment and berry. Onyx is teal-black; Terracotta is copper. Former Violet choices are labelled Sage/Plum with existing preference keys. Sky, Dark, Lime and Midnight palettes are preserved. Shared themes match web/PDF core colours. Small choice-feedback labels use on-surface text while semantic borders/fills retain their meaning; light-theme feedback accents are deeper for tinted canvases.

## Shared learner presentation — 2026-10-13

- Use `AnswerChoice` inside ordinary/offline/master sessions and completed reviews. It owns localized, bidi-isolated number gutters, body wrapping, feedback labels and selected semantics inside `QuestionChoiceCard`. Callers supply reveal-safe `answerCorrect` (null means no grading); active master exams pass neutral selection and no grading. Whole-choice controls use noninteractive Markdown; completed reviews explicitly retain selectable text.
- Use `AppFilterChip` for learner setup/library/offline filters, reading language and related selections. It shares medium rounding, a compact visual-height token, Material's minimum interactive target, readable disabled colors and fixed icon slots. Removable filters retain an explicit remove description; callers own filter state and changes. Use `AppActionRow` for wrapping chip groups.
- Use `AppSaveStatus` for compact local/sync states and an optional guarded action. Callers own state precedence, localized wording, upload scope and allowed actions. Status rendering performs no network/storage work or correctness inference.
- Use `AppRecoveryPanel` for local storage/download/sync recovery with optional safe error details and compact secondary Retry. Keep read reconciliation, retry authority and any explicit discard/resolve actions with the caller. `ErrorState` also uses secondary Retry and shared compact feedback spacing.
- Use `AppConfirmationDialog` for shared medium rounding and title/body typography/spacing. Material retains action order; pass existing guarded `AppTextButton` / `AppDangerTextButton` slots. Finish is a normal command; destructive delete/discard uses the danger control. Do not consolidate different mutation/recovery rules into this presentation helper.
- Use `AppPendingSessionCard` for always-visible Home pending completion and ordinary/master recovery. It combines `AppSectionHeading`, `AppCardBody` and existing guarded actions; pending work must not disappear behind a collapsed section.
- Use `AppMetadataRow` for muted, wrapping counts/categories/tags/dates/durations. It keeps mixed-script fragments isolated and omits blank values; format numbers/dates and decide which information is authorized in the caller.
- Use `AppSectionHeading` for section titles, optional counts/subtitles and trailing actions. `AppSection` uses it within its existing accessible expand/collapse control. Preserve large-text growth and avoid placing unrelated wide actions in a title's trailing slot.
- Use `AppTileGrid` / `AppMetricTile` for Home modes/metrics and result metrics. Smaller tiles center their content and unfinished rows; one width policy calculates up to three columns from available width and font scale, with no font shrinking or fixed text heights. Large text may legitimately require one column. Existing action/ownership guards stay outside metric presentation.
- Reuse `EmptyState` only after a successful empty read or a confirmed empty local filter. Keep failed reads as errors; empty placeholders use shared compact feedback gaps.
- Border widths, tile minimum widths/column limits and rounding allowance join the existing touch-target, compact-height, icon and gutter tokens in `AppLayoutTokens`. Reuse these values when adding related controls.

These conventions describe source implementation. Compilation, actual grid measurement/tap regions, dialog scrolling/focus, translated wrapping, native Markdown selection, theme contrast and TalkBack remain device verification gates.

### Extended adoption

Settings, administration, planner, auth/server/device, transfer, analytics and other remaining chip/dialog callers now use the same wrappers. Keep existing password/danger/uncertain-write action slots and ownership gates; dialog helpers only change presentation. Use `AppMetricRow` for label/value information with font-scale/narrow-width stacking, and `AppProgressMetric` for confirmed localized integer counts and a clamped progress bar. Analytics uses these helpers plus `AppTileGrid` / `AppMetricTile`; charts remain specialized. Additional admin/device/report empty states require completed, error-free reads. Preserve intentional form states such as “all categories” or “none selected”; they are selection summaries, not empty-list errors.

Session bookmarking is a compact labelled trailing action on `QuestionLanguageSelector`, with an end-aligned row when no reading-language choices exist. It independently reads and reconciles state and never occupies width beside the question card. Theme labels resolve bilingual resources for every stored key; `themeShapes` owns per-palette shape roles while shared controls keep consistent semantic roles/tap regions. Stored/API/export keys and core palettes are unchanged.

Home places Did you know immediately after the welcome heading and starts it expanded. Drawer theme names are unique single-word bilingual resources; previews use `previewThemeColors` (the canonical palette resolver) rather than a parallel palette table. `appVerticalScrollIndicator` draws a subtle logical-end track/thumb for real overflow; reserve end padding so it does not cover list actions and preserve native scroll semantics.
