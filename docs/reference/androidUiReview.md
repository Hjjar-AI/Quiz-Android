# Android UI and shell review

Reviewed 2026-10-10. U1–U8 source-complete; [implementation queue](../workPlan.md). Original review evidence is retained below; source fixes are recorded in the closure. Rendered/device verification remains pending.

Scope: authenticated shell, drawer/bottom navigation, shared layout/feedback/theme components, startup/login, settings/profile, question and content editors, planner/groups and exam management/results. Compared relevant native behavior with [web conventions](../../../frontend/docs/guides/UI_CONVENTIONS.md). This is a bounded source review, not proof that every screen renders correctly.

## Original source findings

Source paths below are relative to `app/src/main/java/com/mukhtabir/android/`.

| ID / priority | Reachable behavior and evidence | Correction direction |
| --- | --- | --- |
| U1 / P1 learner, P3 admin | Toolbar titles use exact destination-template matching in `ui/MukhtabirApp.kt:402`. Transfers now register `more/admin/transfers?verified={verified}` and permissions register a query template, while the catalog contains their base routes. Neither matches the fallback, so both display “More”, including entry without a query value. Individual master preview/results, draft detail and master attempt routes also lack explicit titles. Account detail uses “Recently active users” while its body says “Account tools”. | Resolve a canonical route family once and give every reachable detail/editor/attempt an appropriate bilingual title. Keep actual route arguments separate from title lookup. |
| U2 / P1 | The `selectedTab` effect (`ui/MukhtabirApp.kt:324`) clears selection for most nested More destinations; their bottom tabs remain visible. Thus Settings, Planner and similar pages show no selected tab. Question detail instead preserves its originating tab. Drawer selection (`ui/more/MoreScreen.kt:88`) recognizes only equality or a slash suffix, so the permissions query template also loses its selected drawer item. | Define consistent parent/origin selection for nested destinations, normalizing query templates. Preserve originating learner tabs where that is the intended navigation context. |
| U3 / P1 | Drawer availability and bottom-bar availability are separate hardcoded policies (`ui/MukhtabirApp.kt:337,350,1005`). Change password and individual results are “focused” for the drawer but still show bottom tabs; preview and most editors hide both. The idle master exam list also disables the drawer while keeping tabs. These are differing chrome rules visible when moving between closely related screens. This finding does not establish a bypass of a discard guard. | Document which screens deliberately allow tab navigation, then use one route-level chrome policy; preserve busy/session/discard protections independently. |
| U4 / P1 | Settings advertises “Compact spacing”, and the theme changes `LocalAppSpacing` from 16dp to 10dp (`ui/theme/Theme.kt:124`). Home/profile and some lists consume it, but question library, planner, groups, knowledge detail and shared section interiors use fixed 10/12dp gaps. A preference change therefore affects only portions of the app. | Apply density tokens to the intended page/section spacing consistently; retain minimum touch targets and text padding. |
| U5 / P2 | Question editor validation (`ui/questions/QuestionEditorScreen.kt`, validation block before content) is a page-level message, while its fields have no error/supporting-text association. `ui/components/MarkdownField.kt` has no error input. Planner validation at `ui/planner/PlannerScreen.kt:421` similarly reports target/date failures above the fields rather than on the target/date controls. Invalid organization/translation data may be inside collapsed sections without the section opening. | Link field-specific failures to the relevant control and expand/reveal its section on deliberate validation; keep safe server detail summaries for non-field failures. Do not discard drafts. |
| U6 / P1 accessibility | `ui/components/ErrorState.kt` has no default live-region semantics. Some callers explicitly add polite announcements, such as Groups/map, while KnowledgeDetail, AdminAccount and ExamResultsPicker do not. Permissions saved/notice text likewise lacks the live-region treatment used by other editors. Newly inserted feedback therefore has inconsistent announcement semantics. | Provide consistent announcement semantics for non-ticking errors and command outcomes; avoid duplicating caller announcements or making timers live regions. Actual TalkBack announcement behavior remains a device check. |

## Original rendering risks

| ID / priority | Evidence and reproduction | Correction / verification |
| --- | --- | --- |
| U7 / P2 | Several action groups are nonwrapping Rows without scrolling or weights: choice Move up/Move down/Remove (`ui/questions/QuestionEditorScreen.kt:805`), three difficulty chips (`:861`), and shared Restore/Discard (`ui/components/EditorRecoveryControls.kt:29`). Other screens use FlowRow for comparable controls. At narrow width, Arabic or enlarged text, later actions can receive insufficient width or labels can become severely compressed. Source inspection does not establish exact clipping on a device. | Use wrapping layouts for independent actions and verify 320/360dp widths, Arabic RTL, long labels and 200% font size. Maintain logical order and all enabled actions. |
| U8 / P2 | Login/server setup/change password explicitly handle IME padding. The authenticated shell skips the outer `safeDrawing` wrapper (`ui/MukhtabirApp.kt:217`) and its Scaffold/content Column supplies no IME padding. Question editor, planner and account tools have scrolling content but no local IME padding. Scrolling alone does not establish that the last field/action can move above an edge-to-edge keyboard. Manifest has no explicit soft-input mode. | Verify focused bottom fields and Save/validation with the keyboard open under gesture/three-button navigation. Establish one consumed IME-inset policy at the shell or form level, avoiding duplicate padding on change password. |

## Preserved behavior and limits

Shared buttons already use minimum 48dp height; back arrows mirror for RTL. Sections expose expanded/collapsed state and hide collapsed children from semantics while retaining drafts. Imported server addresses stay out of visible manual input. Theme darkness is resolved using the configured dark-theme set; no darkness mismatch was established. Existing guards, native file APIs, encrypted recovery and sensitive memory-only drafts should remain intact during UI corrections.

No P0 ordinary-use failure was established by this review. Exact wrapping/contrast, keyboard behavior, cutouts/insets, focus traversal, TalkBack, chart readability and large-text rendering still require the [manual matrix](../verification/manualVerification.md). No builds, suites, migration work or runtime actions were performed.


## Source closure — 2026-10-10

| Findings | Implemented correction |
| --- | --- |
| U1–U2 | Shared `core/ShellNavigation.kt` normalizes query templates, selects the most specific drawer parent, maps knowledge detail to its map and provides explicit detail/preview/results/account titles. Added a fifth More tab for nested destinations; question detail retains its originating learner tab. |
| U3 | Drawer and bottom bar share one focused-route policy. Change password, individual results, editors, exam list and master attempt hide both navigation surfaces; normal pages keep both. Profile application/refresh retains its separate draft-sensitive policy and existing session/busy/back/discard guards. |
| U4 | Page and section 10/12/16dp vertical gaps now consume the compact-density token across native screens. Small control gaps, padding and minimum touch targets remain deliberate. |
| U5 | Markdown fields accept error/supporting text. Question text/choices/reference/translation/association controls and planner target/date/category controls expose validation. Invalid submits reopen the affected sections using a transient validation-attempt counter, including a repeated identical failure after manual collapse. Existing page-level safe server errors remain available. |
| U6 | Shared errors default to polite announcements. Saved command confirmations and permission notices expose polite semantics; no timer/progress announcements were added. |
| U7 | Choice actions, difficulty chips and recovery actions wrap using FlowRow. Shared page headings put actions below text at narrow widths or enlarged fonts; toolbar titles have weighted width. |
| U8 | Authenticated Scaffold applies and consumes IME insets; content consumes Scaffold padding so child handling does not double-pad. MainActivity explicitly uses adjustResize. Startup/login/change-password local inset handling is retained. |
