# Downloaded ordinary exam and study sessions

Source updated 2026-10-13. Matching Android and backend deployment is required; this is distinct from [offline bank practice](offlineQuestionBank.md).

- Authenticated, owner-scoped `GET /exam/questions/?session_id=…` returns `{session_id, questions}` in the existing API envelope. Study downloads include frozen correct-answer indices, explanations and translated explanations for immediate local feedback after answering. Exam downloads withhold keys and explanations; recall retains server reveal rules. Prefetch neither advances the session nor records unseen question exposure. Single-page study/recall reads include the key only when saved-answer feedback is allowed.
- Ordinary exam/study start, preset start and resume download every page and referenced question image before enabling answers. Failed downloads retain the session and offer Retry. Existing recall/server-reveal and master-attempt flows retain their current contracts; master countdown and grace use the corrected clock formatter.
- Downloaded pages/images, current index and ordered answer changes use the existing encrypted account/server-profile store. Images are stored separately and written once; the combined serialized session is limited to 16 MiB, with a 10 MiB downloaded-image ceiling. No authenticated global HTTP/image cache is introduced. Existing logout/account/server isolation and cleanup gates apply. Restoration requires authenticated account binding; this does not provide a new route around login expiry.
- Navigation reads downloaded pages. Every answer/confidence/reflection change commits locally before entering the queue; ordered changes preserve first-answer evidence. Downloaded exam answers and study answers with valid local keys do not start per-question sync; local save drives existing auto-advance. Older study downloads without keys retain the previous fresh-answer sync fallback. Sync is explicit: read confirmed pages, reconcile acknowledgement or unchanged baseline, navigate with `expected_index`, submit with `expected_slot`, then confirm by reading before removing the queued change. Confirmed prefixes can complete while the remaining queue survives failure. There is no automatic uncertain replay.
- Study feedback appears after a locally saved answer using the downloaded frozen key, explanation and selected reading language. The chosen wrong answer and the correct choice have distinct highlights and text labels. Exam feedback remains hidden until results. A divergent saved slot offers explicit device/server choices; keeping the server answer removes that question's local pending changes, while keeping device changes rebases their first precondition against the displayed server slot. Subsequent writes still use the backend's locked precondition. The server retains existing first-attempt grading and learning rules; local feedback does not establish server submission or learning credit.
- Explicit sync uses one validated full snapshot initially, then fresh individual question reads for normal slot preconditions/confirmations. Cached acknowledgement alone never removes queued data: it is read again, with full-session fallback if the current question differs or its read returns 404. Lost responses, mismatched indices, changed slots and missing sessions retain recovery; acknowledged data can be checked without moving an expired/completed session. Full fallback reads may still occur during reconciliation. Individual presentation reads retain existing per-session/question deduplication.
- Server pause and server finish require confirmed queued answers. Exam time continues during network loss; **answers must reach the server before its existing deadline**. Reconnection after expiry does not authorize late exam submissions: rejected pending changes remain on the device. This feature does not guarantee timed-exam completion during an outage lasting beyond the deadline. Long-running study remains synchronizable while its session exists and remains active.
- Remaining/additional time uses an isolated left-to-right clock inside localized labels: `MM:SS` below one hour, `HH:MM:SS` thereafter. This fixes the reported reversed `59:233` display without changing server time rules.

Checks: four production Python ASTs; eleven production Kotlin lexical/import/resource checks; resource XML and bilingual placeholders; whitespace checks. No Gradle, compilation, suites, migrations/setup, database writes, deployment, or device/runtime verification. ## 2026-10-13 nonblocking synchronization and local study completion

Explicit sync freezes the initial queue length and retains fresh expected-index/slot reads/writes. Answering and cached navigation continue during its network awaits; each confirmed head is removed from the latest local queue, preserving appended revisions, other answers, the current index and local completion flags. Answers added after Sync began stay pending for another explicit Sync. Conflicting-slot choices, pause, server finish and duplicate Sync remain guarded; storage errors still disable unsafe local changes. A conflict on one question does not discard other pending answers.

Downloaded **study** sessions offer Finish on device in the finish confirmation. This durably freezes a local completion flag and the displayed timer, stops new answer/confidence/reflection changes, and permits local review/navigation and leaving without a server pause. Encrypted restoration preserves that state. A later explicit Sync confirms queued answers, then uses the existing guarded server-finish/recovery path. Server results/history/learning credit and server elapsed time remain authoritative; the frozen local display does not change the server's study time calculation. Exam and recall completion rules are unchanged; no local exam finish or late exam-answer acceptance was added.

Home reads the encrypted local completion flag to show a pending-confirmation reminder above dashboard sections. It also counts finished offline-pack summaries without confirmed results. Resume/manual refresh rechecks local storage; failures retain known pending data and expose Retry. The actions reopen existing quiz/offline flows and never start synchronization automatically.

An explicit Pause and leave request can now synchronize pending downloaded answers first. The modal confirmation keeps the action guarded until all saved changes in the same session are acknowledged without conflict/storage/recovery errors, then uses the existing server-confirmed pause flow. Sync/pause failures remain visible and retain local material; uncertain writes still require reconciliation. Pending Finish blocks pause. Pause can also leave a session whose question download failed, since it requires the owned session ID rather than question material. Locally finished study retains its existing local exit path and timed-exam authority is unchanged.
