# Android working rules

- Read [README.md](README.md) and current production source first. Preserve unrelated edits and existing authorization; do not commit unless requested. Complete authorized work, continue independent work while clarification is pending, and ask only for missing decisions.
- No migration inspection/changes/setup, automated-suite inspection/work, Gradle/build/compilation/packaging, or version changes without an explicit request. Supplied build logs authorize source troubleshooting only. Production study/exam modules are application code, not suites. Lightweight production-source/XML/lexical/whitespace checks are allowed; never imply compilation, deployment, device, schema or concurrency verification.
- Preserve native architecture/DI/Compose patterns. Trace affected callers, DTOs and current Django/Vue contracts; never invent endpoints, fields, capabilities or idempotency. Handle nullable/legacy/fractional responses. Keep serialization companions accessible and experimental Compose opt-ins scoped; check actual component signatures.
- Gate destinations and handlers independently; Django is authoritative. Own-question permissions use current `owned_by`. Keep personal History user-scoped and all-user History separately gated. Refresh affected profiles/selectors after confirmed writes without discarding drafts; use runtime config for limits/roles/pagination.
- Set busy guards before launching writes; cancel stale reads and propagate cancellation. Preserve drafts, selections, readable content and confirmed success. Reconcile uncertain writes by current state/receipts before explicit action; never automatically replay answers, toggles, creates, navigation, Finish or sync. Read failure is not an empty/saved result. Confirm destructive/discard/finish actions; failed pause must not exit. Consume practice intent only after initialization/permission checks.
- Scope private state to account/server, retain frozen completion identities/bodies and use existing encrypted recovery. Keep other sensitive drafts memory-only, authenticated HTTP uncached, temporary files cleaned and secrets out of logs. Follow README's offline/profile/expiry policy; imported file metadata never authenticates or merges servers.
- Preserve snapshots, case-before-question order and exam/recall reveal guards in every reader/translation/review. Reuse bilingual resources/shared tokens/controls; check XML keys/placeholders, RTL, 48dp targets, large text, focus, reduced motion and themes/fonts. Do not announce ticking timers. Coordinate theme changes with web/PDF palettes.
- Preserve configurable HTTP/private HTTPS: selected-origin HTTP only, valid TLS chain/hostname with system/user CA trust, no trust-all validation. Use actual SDK/property configuration, never guessed phone hosts or committed machine paths.
- Fresh SQLite setup through the user's normal `python start.py sqlite` generates initial migrations only when app migration folders are absent; existing files change that behavior. This does not authorize inspecting/running setup. See [backend startup](../backend/docs/guides/START_HERE.md).
- Keep only current behavior, unresolved work and verification limits in README; remove obsolete history rather than archiving it. Fix documentation links when consolidating. Record actual runtime evidence only when obtained. If a visible five-hour allowance reaches 20% remaining, finish the current step and stop; never infer usage.
